# Net performance of a frozen intraday policy

```bash
python3 -m scripts.policy_validation --ledger ledger.json --as-of-ms 1702000000000
```

The CLI emits JSON, the input SHA-256, the cutoff, and the inference settings. It runs offline using the Python standard library. Supply one JSON ledger per frozen policy and evaluation period. Attach it and the output hashes to the experiment record. A complete example can be constructed with `fixture()` in `tests_py/test_policy_validation.py`. Its dates and fills are synthetic.

## Ledger contract

| Required field | Meaning |
|---|---|
| `policy_id`, `dataset_id`, `benchmark_id` | Nonempty identifiers for the frozen decision rule, exact source data, and predeclared comparison policy. Reconcile against the immutable specification. |
| `source_kind` | One of `synthetic`, `historical_simulation`, `paper_fills`, `broker_fills`. This identifies the submitter’s claim. The CLI records `source_verification=user_declared_only` for every source. |
| `calendar_source` | The independent source used to enumerate **all** eligible sessions, including holidays/closures as applicable. Carry the source version or hash. A reviewer must check coverage against this source. |
| `capital_basis`, `initial_equity_cents` | Describe and supply opening marked research portfolio equity, in USD cents. Both policies start on the same basis. This return denominator is distinct from a prop account’s permitted loss capacity. The calculation assumes a self-financing portfolio, flat at each close, with no deposits, payouts, overnight marks or financing charges outstanding. |
| `cost_basis` | `reference_prices` or `fill_prices`. Reference-price simulation requires explicit modeled execution costs. Actual or paper fill-to-fill gross P&L already reflects slippage and requires `slippage_cents=0` to prevent a second charge. Explicit zero fees/costs require source evidence. |
| `evaluation_stage`, `policy_frozen_ms` | Stage is `development`, `validation`, `holdout` or `forward`. Freeze the rule, size, cost model, baseline, test endpoints and resampling design before the first included session. Keep separate ledgers for each stage. |
| `family_size` | Total attempted policies including failed and unpublished attempts. Use `null` for unknown history, which withholds selection-adjusted bounds. |
| `independent_trial_sharpes` | Optional diagnostic input. Supply `null` unless the complete family consists of defensibly independent trials with comparable per-session Sharpe estimates at the same sampling frequency. When supplied, the list length must equal `family_size`. |
| `sessions`, `trades` | Arrays described below. Empty arrays produce unavailable statistics and zero evidence. |

Each `sessions` entry has integer `open_ms`, `close_ms`, `completed_trades`, and `benchmark_net_cents`. Supply consecutive eligible sessions in order, one per Eastern close date. Record **zero** completed trades on an idle session. Supply a cost-inclusive benchmark result on every session. A cash/no-trade baseline earns zero under the stated zero-cash-return convention. For a strategy benchmark, reconcile its daily net values independently and verify comparable risk. The tool checks dates, counts and nonoverlap. A holiday gap and an entirely omitted session both require external calendar evidence to distinguish.

Each `trades` entry represents one completed round trip, with all partial fills and exits aggregated by position. Supply unique `id`, latest `feature_available_ms`, `decision_ms`, `submitted_ms`, `entry_ms`, `exit_ms`, signed `gross_cents`, nonnegative `fees_cents`, `slippage_cents` and `other_costs_cents`, positive `initial_risk_cents` for the whole position, positive whole `contracts`, and nonempty `exit_reason`. Include timeouts and losses. All monetary columns apply to the **whole** round trip. Every decision and exit must lie within the same declared session, features must have been available by the decision, and the evaluation cutoff must cover each session close. Reconcile upstream unfilled signals, cancelations, trade grouping, partial fills and all source prices independently. The CLI cannot reconstruct missing executions from first-touch labels.

## Reading the results

- Trade expectancy equals total net cents divided by all completed trades. The mean R multiple averages each trade’s net P&L divided by its own initial risk. A 67% win rate can still produce a loss. `profit_factor` uses gross positive net outcomes divided by the absolute sum of negative net outcomes. Undefined ratios appear as `null`.
- Each policy’s per-session return divides its net cents by its own opening marked equity. Idle sessions contribute zero. The Sharpe ratio uses the sample standard deviation of session returns and a zero cash-return reference. Sortino uses root mean squared downside across **all** sessions. Both ratios remain in native session frequency. Drawdown and time underwater use session closes. Intraday drawdown breaches require a separate marked account path.
- Signed expected shortfall is the empirical mean return in the worst 5%, with fractional mass at the boundary. Short samples can make it equivalent to one worst observation. This report does not infer an account-liquidation probability from session closes.
- Two predeclared one-sided endpoints assess per-trade expectancy and mean paired session-return improvement over the designated benchmark. Circular moving-block resampling selects the same consecutive sessions for both series, retaining the trade count in each selected session. Each replicate sums P&L and divides by pooled trade count. The per-endpoint percentile level is `0.05 / (2 * family_size)` for a nominal joint one-sided 95% family target. This Bonferroni allocation accommodates dependence between hypotheses. Actual coverage depends on the block bootstrap approximation. The default block length is three eligible sessions. Try plausible predeclared dependence lengths and record sensitivity. Wrapping joins the last and first observations, and assumes an approximately stationary evaluation segment. A structural break, repeated holdout use or incomplete search history can invalidate the inference.
- Bounds require at least 30 sessions, 10 block lengths, two trades and at least 10 Monte Carlo draws in the adjusted tail. Short samples, undefined resampled expectancy and degenerate resampling distributions withhold the bounds. These are numerical screening floors. Adequate power, effective independent observations and genuine economic benefit require separate assessment.
- Probabilistic Sharpe, Deflated Sharpe and minimum track length are conditional diagnostics under the papers’ asymptotic independent-return assumptions. The implementation uses the empirical skewness and **ordinary** kurtosis at native frequency. It checks against the published Appendix A.3 numerical example. DSR additionally models the expected maximum Sharpe statistic under a zero-mean null with independent selection trials. Correlated variants cannot be counted as independently verified trials. Leave `independent_trial_sharpes` null when this information is missing. Serial dependence, changing regimes or heavy tails can make these diagnostic probabilities misleading. [The Sharpe Ratio Efficient Frontier](https://www.davidhbailey.com/dhbpapers/sharpe-frontier.pdf) · [The Deflated Sharpe Ratio](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)

Every ledger returns `EDGE_NOT_ESTABLISHED`. Independent source reconciliation, locked holdout governance, comparable risk, adverse execution testing and forward evidence are separate review steps. Estimating the probability of backtest overfitting or running a Reality Check / SPA test requires the aligned performance matrix across candidate policies, including failures. The one-policy ledger cannot supply that matrix. [The Probability of Backtest Overfitting](https://escholarship.org/uc/item/4hn4t174)
